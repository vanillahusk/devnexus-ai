# 作品集文章数据说明

## 为什么不直接抓取技术博客

社区文章会公开展示并进入 RAG 索引，因此必须明确内容归属。

- Stack Overflow 的公开贡献采用 CC BY-SA，不适合在没有逐篇作者、原链接和许可证说明的情况下直接搬运。
- Spring Guides 的代码与正文许可证不同，正文带署名且禁止改编，不适合翻译后作为自己的社区文章。
- 未明确许可证的博客、公众号和聚合数据集不进入项目。

当前文章集以项目自己的冻结 RAG 评测语料为数据源，围绕可靠消息、微服务治理、
可观测性、RAG 和受控 Agent 重新组织为原创中文工程笔记。每篇文章的外部链接只作为
延伸阅读，不复制官方正文。

## 数据规模

默认导入 30 篇文章，来源文件为：

```text
paicoding-web/src/test/resources/rag/expanded-hard-articles.tsv
paicoding-web/src/test/resources/rag/expanded-hard-queries.tsv
```

导入器只选择编号 `3001`～`3030` 的核心文章，不导入评测用干扰文档、下线文档和拒答问题。

## 导入方法

先启动 MySQL、Redis、RocketMQ 和社区 Web 服务，再执行：

```bash
DEVNEXUS_USERNAME='<管理员账号>' \
DEVNEXUS_PASSWORD='<管理员密码>' \
node scripts/import-portfolio-articles.mjs
```

脚本使用登录和发文 HTTP 接口，不直接写数据库。文章会经过正常的
`ArticleWriteService → MySQL 事务 → 知识 Outbox → RocketMQ` 链路。

重复运行时，标题已经存在的文章会跳过。

## 替换遗留文章

归档现有公开文章属于数据变更，必须显式二次确认：

```bash
DEVNEXUS_USERNAME='<管理员账号>' \
DEVNEXUS_PASSWORD='<管理员密码>' \
ARCHIVE_EXISTING=true \
CONFIRM_ARCHIVE=YES \
node scripts/import-portfolio-articles.mjs
```

导入器先通过管理员文章删除接口软删除不属于新数据集的公开文章，再发布缺失的新文章。
软删除会触发文章下线和知识索引事件；不会执行直接 SQL 删除。

建议先备份本地数据库。不要在包含真实用户投稿的环境中启用 `ARCHIVE_EXISTING`。

## 能力边界

- 这些内容是作品集演示与 RAG 学习语料，不冒充真实社区用户投稿。
- 正文由固定结构从项目事实生成，适合演示检索、引用和文章详情，不代表专业出版物。
- 正式公开运营社区时，应只导入作者明确授权的内容，并在数据模型中保存作者、来源和许可证。
