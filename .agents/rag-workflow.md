# RAG 与 Agent 工作流

本规则约束 RAG/Agent 任务的技术边界；实际工作范围以用户要求和仓库现状为准。

## 架构边界

- MySQL 是文章正文、状态和版本的事实源，不以向量库反向覆盖业务数据。
- 文章新增、更新、删除通过 Outbox 与 RocketMQ 发布版本化索引事件。
- 索引事件只携带事件 ID、文章 ID、文章版本、操作和发生时间等定位信息，不携带完整 Markdown 正文；消费者从事实源读取当前快照。
- AIGC 服务消费索引事件并维护检索索引；消费必须幂等、可重试、可死信、可重放。
- Ragent 是当前向量知识库与检索能力的归属系统；其他向量库只在任务明确需要时引入。
- 旧 SQL `LIKE` 检索只能作为兼容或降级路径，不应被描述为现代向量 RAG。

## 实施顺序

1. 先固定数据源、文档 ID、版本、可见状态和删除语义。
2. 再完成文章到索引的增量同步闭环。
3. 建立固定评测集和旧方案基线后，才优化分块、召回、重排和 Prompt。
4. 检索结果必须带文章、片段和必要的版本信息，回答应支持引用与拒答。
5. 先把可评测 RAG 做稳，再增加 Agent；Agent 不代替检索质量建设。

## 索引正确性

- 同一文章的新版本不得被旧事件覆盖；使用文章 ID、版本号和事件 ID 共同保护。
- 删除或下线文章必须从检索结果中消失，并支持对账修复漏事件。
- 分块策略保留标题、层级、来源和顺序，避免无法回溯到原文。
- 同一事件重复消费结果一致；失败进入有界重试和死信恢复流程。
- 建立 MySQL 与索引库的数量、版本、状态校验，不以“发送成功”代替“索引生效”。
- 收到旧版本事件时不机械重建所有历史版本；读取 MySQL 当前快照并使索引直接收敛到最新状态，或把已明确过期的事件安全丢弃。
- 下线/删除保留包含最新版本的墓碑状态；正文删除后，迟到的 ONLINE/UPDATE 事件仍不得复活文章。

## 全量重建与增量并发

- 全量重建开始时记录 Outbox/变更日志水位和新索引 Generation，不直接覆盖当前在线索引。
- 基于一致性快照构建新 Generation 后，将起始水位之后的增量事件重放到新 Generation。
- 只有新 Generation 追平切换时的当前水位，并通过版本/状态对账后，才能原子切换查询别名。
- 旧 Generation 延迟删除，保留短期回滚窗口；切换失败继续使用旧 Generation。

## 评测与安全

- 使用固定问题集分别记录召回率、MRR/nDCG、引用命中、拒答正确率、延迟和成本。
- 每次优化与同一基线对比，不用少量主观示例宣称效果提升。
- 检索层过滤未发布、已删除和无权限内容。
- Prompt 注入、敏感内容、超长上下文和恶意文档需要显式防护。
- 模型或检索服务不可用时有超时、熔断和明确降级，不拖垮主站。
- RRF 分数只用于候选融合排序，不直接作为统一拒答阈值；拒答综合 Reranker 相关度、精确匹配、候选差距、有效 Chunk 数、引用覆盖和问题类型。
- Java 类名、错误码等精确问题允许高质量关键词命中弥补一般的向量分数，并在固定评测集中单独覆盖。

## Agent 边界

- 第一版只做单 Agent、少量只读白名单工具和有限步骤编排。
- 工具参数需校验，设置超时、最大轮数、Token 和调用次数预算。
- 步数、工具次数、截止时间、Token 预算和已调用参数签名由服务端状态机强制执行，不能只依赖 Prompt。
- 工具调用签名在去空白、大小写和必要参数规范化后去重，防止语义相同的循环调用。
- 工具返回内容统一视为不可信资料，与系统指令结构隔离，正文中的指令不得提升权限。
- `getArticleDetail` 只能读取此前检索证据已经返回的 articleId；主站事实源必须在 DAO 层强制 ONLINE + 未删除，使用内部令牌，且不得复用会增加阅读量或足迹的公开详情接口。
- 无证据直接回答只允许服务端识别的问候、身份说明等非知识问题；知识问题即使 Planner 请求 DIRECT 也必须转入可信 RAG。
- Agent HTTP 响应只返回最终答案、低敏工具摘要和引用，不序列化工具正文、Prompt、异常消息或降级检索上下文。
- 高风险写操作默认禁止；未来确需加入时必须有用户确认、审计和补偿方案。
- 记录检索依据、工具调用、耗时和失败原因，但不记录密钥或完整敏感正文。

## 真实验证要求

- Ragent、模型和 RocketMQ 实测必须先做依赖预检，并采用有界运行与清理。
- Mock 只能验证适配器逻辑；只有真实在线、更新、下线和查询闭环通过，才能宣称 RAG 索引链路跑通。
- 验证报告应区分代码完成、Mock 证据、真实依赖证据和仍待验证项。
- 冻结题集真实 Embedding/Reranker 评测使用 `community/scripts/run-qwen3-dense-hybrid-evaluation.sh`；只从环境变量读取密钥，最多运行 300 秒、Maven 堆上限 512MB，不启动服务或容器。
- HY3 生成评测使用 `community/scripts/run-hy3-generation-evaluation.sh`，均匀抽取 8 条可回答问题、并发 2、最多运行 300 秒；检索/拒答与生成分开评测，避免重复消耗模型额度。
- HY3 Planner 评测使用 `community/scripts/run-hy3-agent-planner-evaluation.sh`，固定 8 条动作任务、并发 2、最多运行 300 秒；只评估真实 Planner 的结构化动作选择，不执行工具，不冒充 Agent 端到端质量。
- WSL 本机代理不可用时，只能通过显式 `MODEL_API_DIRECT=true` 切换直连；必须先用单次不输出正文的 HTTP 状态探测确认可达，不能把代理连接失败记作模型质量失败。
- Dense/Hybrid 检索指标与 Reranker、拒答、生成质量分别记录；不得用 Recall@5/MRR 提升替代最终答案正确率结论。

## 可观测性边界

- Prometheus 标签只使用 operation、status、retrieverType、modelName、fallbackType 等低基数字段。
- userId、articleId、eventId、query/queryHash 和 conversationId 进入脱敏日志或 Trace，不作为指标标签。
- Prompt、文章正文、用户对话和完整 MQ payload 不写入普通日志、Span 标签或 DLQ 页面。
